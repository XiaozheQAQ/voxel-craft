# Runtime Plan

Tracking doc for the migration of `index.html` from a single-file Minecraft-like
voxel game into **Runtime 0.1** — an agent-programmable voxel game runtime.
Source of truth for phase status. See `RUNTIME_ARCHITECTURE.md` (internal
structure), `RUNTIME_API.md` (public API), `VMP_SPEC.md` (mod protocol),
`MIGRATION_NOTES.md` (before/after log), `TEST_MATRIX.md` (regression log).

## Goal

Agent-programmable voxel game runtime. Single HTML file, no Node/npm/build,
no server, double-click to run. Third-party mods (`.vmod`, plain JS text)
loaded via a documented `defineVoxelMod(api => ...)` surface, generated by
any Coding Agent from a formal prompt protocol (VMP/1).

## Non-goals (v0.1)

No React/Vue/Three/Babylon/bundler/TS build. No renderer rewrite, no WebGL
stack change. No real sandbox (mods run same-JS-realm, trusted). No
networking, no account system, no chunked/dirty-mesh renderer rewrite.

## Original architecture (pre-migration baseline)

Everything lived in one IIFE (`index.html:213-1302`), plain closures over
module-level `let`/`const`. No registry, no event system, no plugin concept.
See the coupling map below — this is what each phase incrementally cuts
through with facades, without rewriting the underlying implementation.

| Shared state | Writers | Readers |
|---|---|---|
| `pos/yaw/pitch/velY/grounded` | `updatePhysics`, mousemove handler, `die()` respawn, `regenBtn` | `updatePhysics`, raycast, render/arm draw, `tryPlace`, `posText` |
| `currentTarget` | `loop()` | `updateMining`, `tryPlace`, highlight draw |
| `inventory` (numeric-id keyed) | `updateMining`, `tryPlace`, `regenBtn` reset | `tryPlace`, `refreshHotbarCounts` |
| `world`/`heightMap` | `setBlock`, `generateWorld` | `getBlock/isSolid/isSolidReal/buildMesh/raycastBlock/collidesAABB` |
| `rebuildWorldMesh()` | 3 independent call sites (mining, placement, regen) | — |
| `health/lastDamageTime/isDead` | `applyDamage`, `die()`, `loop._regenAccum` hack | `updateHeartsUI`, fall-damage branch |
| `keys{}/mouseDown/selectedHotbar` | input listeners | physics, mining, hotbar UI |
| `HOTBAR` (fixed 6-array, numeric ids) | `buildHotbarUI` | `tryPlace`, hotbar refresh |

## Phase 1 — done

Added (index.html, before the `World data` section, formerly line ~308):
`RUNTIME_VERSION`/`API_VERSION`/`VMP_VERSION` constants, `EventBus`
(Map-based, `on/once/off/emit/emitCancelable`, reused cancelable-event
object to avoid per-frame allocation), `createIdRegistry(kind)` factory
(string-id ↔ numeric-id, namespace validation, `core:` protection via
`withCoreRegistration`), `BlockRegistry = createIdRegistry('block')`, and
a top-level `runtime` const exposing `{version, events, registry}`.

Nothing existing calls into any of this yet — verified via `new
Function(scriptSource)` syntax check and full manual regression pass (see
`TEST_MATRIX.md`). No core blocks registered yet (that's Phase 2).

## Phase 2 — done

Registered `core:air/grass/dirt/stone/sand/wood/leaves` into
`BlockRegistry` in exact `BLOCK` enum order, sourced from
`BLOCK_HARDNESS`/`BLOCK_TILES` (no data duplication). Numeric id match is
asserted at boot (`CORE_ID_MISMATCH` if it ever drifts). Internal code
(`generateWorld`, `buildMesh`, `isSolid`, mining, placement, inventory,
hotbar) is untouched — still reads `BLOCK.X` directly. Verified via
browser reload: identical deterministic spawn position, no console errors,
no mismatch thrown. See `MIGRATION_NOTES.md` 002.

## Phase 3 — done

Added `runtime.world` and `runtime.player` facades (after `raycastBlock`,
before the mining/placement section) wrapping existing functions 1:1.
Collapsed the 3 independent `rebuildWorldMesh()` call sites (mining
completion, `tryPlace`, `regenBtn`) into `runtime.world.setBlock`/
`runtime.world.regenerate`; rewired those 3 call sites accordingly. IDs
stay internal numeric `BLOCK.*` — string-id boundary deferred to
Phase 4/6. Verified via a temporary, removed-before-commit
`window.__voxelDebug` hook exercising every facade method, plus a clean
boot regression. See `MIGRATION_NOTES.md` 003.

## Phase 4 — done

Added `ModHost` (validate → apiVersion check → scoped `api` → `setup`/
`start` in try/catch → structured errors, never a bare throw) and the
globally-exposed `defineVoxelMod`/`window.defineVoxelMod` (deliberate
exception to "no globals" — `.vmod` files in Phase 8 load as separate
`<script>` tags outside the closure). Wired `game.tick`, `block.break(
.before)`, `block.place(.before)`, `player.jump`, `player.damage`,
`player.death`, `player.respawn` at their exact call sites. Shipped
`dev.superjump`, gated behind `?mods=1`, proving the full chain
(`defineVoxelMod` → `ModHost` → scoped api → event → real gameplay
effect) end-to-end. See `MIGRATION_NOTES.md` 004.

Known gap, intentionally deferred to Phase 5: the scoped `api` is
unfiltered (no permission gating yet) and untracked (no per-mod ownership
for auto-cleanup — `unload` doesn't exist yet).

## Phase 5 — done

Added `PERMISSION_MAP` + `gate()` (undeclared-permission calls throw
structured `PERMISSION_DENIED` instead of running), ownership-tracked
`events.on/once` (subscriptions tagged into a per-mod `ownedSubs` Set),
`dependencies`/`conflicts` checks in `register()`, and
`ModHost.unload(modId)` (calls `stop()`/`unload()`, then auto-cleans every
owned subscription). `dev.superjump`'s manifest updated to declare
`player.read`+`player.modify`. Pure `ModHost`-internal — no gameplay call
site touched. See `MIGRATION_NOTES.md` 005.

## Phase 6 — done

Grew the atlas to 8x8 (core keeps tiles 0-7, 8-63 free for mods);
`registerCustomBlock`/`api.blocks.register` paints spare tiles
procedurally and extends `BLOCK_TILES`/`BLOCK_HARDNESS`/`inventory` with
the new numeric id so existing mining/placement/hotbar code needs zero
changes. `api.items` is an explicit alias of blocks (no separate
registry — nothing distinguishes them yet). New `api.entities`
(`registerType/spawn/get/query/remove/setState`), a plain `Map`-based
store ticked/drawn unconditionally each frame from `loop()`, reusing
`buildBox`/`drawArmPiece` for rendering (no new shader). Shipped
`dev.crystalblock` (Test C) and `dev.chaser` (Test D, a real chasing/
damaging enemy) behind `?mods=1`. See `MIGRATION_NOTES.md` 006.

Known gap, intentionally deferred: `solid:false` on a custom block is
stored but not honored by `isSolid()`/`collidesAABB()` — those still only
check "is this cell non-AIR", unaware of the registry. Documented, not a
blocker for anything planned in Phases 7-10.

## Phase 6.5 — done (contract reconciliation)

Not a feature phase — reconciled the actual implementation against
`VMP_SPEC.md`'s own promises before `.vmod` makes any of it externally
consumed. Headline fix: mod-facing `world.getBlock/setBlock` and
`player.getInventory/giveItem/takeItem` now speak string ids
(`toPublicBlockId`/`toInternalBlockId` at the `ModHost` boundary only —
every internal hot path, `runtime.world`/`runtime.player` themselves
included, stays numeric, untouched). `dev.crystalblock` rewritten to
prove string-id-only mod code. Entity spawns now ownership-tracked.
Definition re-registration after unload explicitly decided as
unsupported (Option B — documented, not silently undefined). New
`player.step` event (cell-change-triggered, not per-frame). Stale
future-tense docs corrected throughout. Full detail: `MIGRATION_NOTES.md`
007A.

## Phase 7 — done

`runtime.time` (Runtime-owned scheduler, ticks only during active
gameplay — see clock-semantics decision below), `runtime.ui` (text-only,
no HTML injection surface), `runtime.effects.flashScreen` (own DOM
element, doesn't fight the built-in damage flash), `runtime.storage`
(namespaced, unload-safe), `runtime.input` (`{code}` payloads, never raw
`KeyboardEvent`). `api.audio` stays a `NOT_IMPLEMENTED`-throwing stub —
discoverable but honest. `api.game` limited to `getVersion`/`getState`
only — no `registerMinigame`, by design (Part B8). Passive regen migrated
off `loop._regenAccum` onto `timeScheduler.every`, verified behaviorally
identical via a real ~10.5s wall-clock wait. Ownership extended to cover
timers/entities/UI. **Found and fixed a real bug while auditing Part G**:
`EventBus.emit`/`emitCancelable` had no per-listener error isolation — a
throwing mod handler could break the game loop for everyone. Fixed with
a shared `safeInvoke` + mod-attributed structured error reporting. Full
detail: `MIGRATION_NOTES.md` 007B.

All five mod acceptance tests (A–E) pass, verified in-browser, both
individually and via a dedicated ownership-destruction test exercising a
mod that owns one of every resource type at once. See `TEST_MATRIX.md`.

## Phase 8 — done (`.vmod` import: capture → validate → activate)

`captureDefinition(source)` executes trusted `.vmod` text with a LOCAL
`defineVoxelMod` collector (via `new Function('defineVoxelMod', source)`)
that shadows the real global of the same name — a captured mod's
`setup()`/`start()` literally cannot run until the Runtime explicitly
calls `ModHost.activate()` afterward. `ModHost` split into `validate()`
(manifest/apiVersion/dependency/conflict checks) and `activate()`
(scoped-api build + `setup()`/`start()`), with `register()` (the
production `defineVoxelMod` path) now just `validate` then `activate` —
one source of truth. `activate()` rolls back any owned resources a
throwing `setup()` created before failing (reusing `unload()`'s own
`cleanupOwned`, now shared). Re-importing a mod that previously
registered persistent block/item/entity-type definitions produces a
human-readable `DUPLICATE_DEFINITION_ON_REIMPORT` error instead of a
bare registry code. `ImportRecord`/`ImportManager` (`runtime.mods`,
deliberately not `api.mods`) plus a minimal dev-facing file-picker
control. No enable/disable toggle — deliberately not built, matches the
Phase 6.5 definition-permanence decision. See `MIGRATION_NOTES.md` 008.

## Phase 8.5 — done (machine-owned API metadata)

`PUBLIC_API_META`/`PUBLIC_EVENT_META` — plain array literals, no schema
framework — are now the single source Phase 9's prompt generator reads
from. `auditApiMetadata()` (opt-in `?dev=1`) cross-checks them against
`ModHost`'s real `PERMISSION_MAP` and **found a genuine bug on first
run**: `api.storage.get/set/remove` were documented and spec'd as gated
behind the `storage` permission but were never actually wired into
`PERMISSION_MAP` — fixed immediately, audit re-run clean. See
`MIGRATION_NOTES.md` 008.

## Phase 9 — done (VMP/1 Agent Prompt generation)

`runtime.vmp.generatePrompt(userRequest)` builds all 7 VMP/1 sections
(added `[VMP EVENTS]` to the protocol, `VMP_SPEC.md` updated) entirely
from Phase 8.5's metadata — no hand-duplicated prose, so `RUNTIME_API.md`
and the generated prompt cannot independently drift the way two
hand-maintained documents could. Namespace rule (`manifest.id` →
resource namespace) is a real function (`deriveResourceNamespace`), not
just prose, and the prompt's worked example is computed through it.
Verified: contains every API needed by all 5 acceptance tests, zero
internal-id leakage, structured error on invalid input. **Documentation-
only agent simulation** (a brand-new `demo.healthwatch` mod, authored
from the generated prompt alone) exercised the complete chain — including
a first-attempt permission mistake that the Runtime correctly rejected,
followed by a successful fix and re-import. See `MIGRATION_NOTES.md` 009.

## Phase 10 — done (Vibe Workshop UI)

`WorkshopController` (new `/* === Vibe Workshop === */` section in
`index.html`) is a pure consumer of everything built in Phases 1-9 —
Create/Mods/Errors tabs, entry button in the existing start overlay,
opening it releases pointer lock via the existing handler (no new pause
model), permission preview before activation (via new
`ImportManager.beginImport`/`confirmImport`, which required zero
`ModHost` changes since `validate`/`activate` were already split),
honest "Unload for this session" with no enable/disable toggle, root-cause
error unwrapping for permission errors, and an optional-but-implemented
`generateFixPrompt`/"Copy Fix Prompt". Full design record in
`WORKSHOP_UX.md`. See `MIGRATION_NOTES.md` 010.

## Runtime 0.2 — Community Backend Foundation (checkpoint reached)

Edge Function) while preserving the Runtime's core security boundary:
